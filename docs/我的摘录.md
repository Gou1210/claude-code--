## Claude Code 机制分层关系

**核心原则：需要强制执行的东西，交给 settings / permissions / hooks，不要只靠 memory 或 skill。**

### 三层架构

| 层级 | 机制 | 本质 | 强制力 |
|------|------|------|--------|
| **硬配置层** | settings / permissions / hooks | 系统级约束 | 强制执行，不依赖 Claude 理解 |
| **说明层** | `CLAUDE.md` / rules / auto memory | 上下文输入 | 依赖 Claude 理解与配合 |
| **能力层** | skills / agents | 按需调用的扩展 | 同样是输入，不是约束 |

### 为什么 skill 不在"强制执行"讨论里

skill 的职责是"扩展能力"，不是"施加约束"。
- skill 是流程封装（发布流程、排查清单）
- 调用时才加载，不调用就没有
- 它和 memory 一样，都是"告诉 Claude 怎么做"，而不是"阻止 Claude 做什么"

### 选择决策

| 需求 | 放哪里 |
|------|--------|
| 每次都要知道的规则 | `CLAUDE.md` |
| 只对某些目录生效 | rules + `paths:` |
| 流程步骤（发布/排查） | skill |
| Claude 自己学会的偏好 | auto memory |
| 强制使用某个模型 | settings |
| 禁止某些危险命令 | permissions |
| 每次提交前自动检查 | hooks |

## 上下文分流规则

**临时流程** → 放进 **skill**
- 发布流程、PR review 流程、故障排查 checklist 等
- 按需加载，不会每个任务都塞进上下文

**高噪音任务** → 交给 **subagent**
- 大范围搜索、长日志排查、大量文件阅读总结
- subagent 在独立上下文工作，主会话只拿结果摘要

**上下文控制链**：
1. 长期规则 → `CLAUDE.md`
2. 高频流程 → skills
3. 高噪音任务 → subagents
4. 会话变重 → `/compact`
5. 任务切换 → 新开 session

## CLI 常用命令

```bash
# 会话管理
claude --continue          # 继续最近一次会话
claude --resume            # 打开会话选择器
claude --resume <name>     # 按名称恢复会话
claude --from-pr <number>  # 按 PR 恢复会话

# 并行工作流
claude --worktree feature-auth    # 创建隔离 worktree 并启动新会话

# Plan Mode
claude --permission-mode plan                      # 交互式 plan mode
claude --permission-mode plan -p "分析认证系统"    # 非交互分析

# 管道
cat error.txt | claude -p "解释这个错误" > output.txt
```

## 权限体系

### 四层结构

| 层级 | 控制什么 |
|------|---------|
| Mode | 遇新操作的默认倾向 |
| Rules | 哪些工具直接过/问/拒绝 |
| Directories | 能访问的路径范围 |
| Sandbox | 系统级执行隔离 |

### 规则匹配顺序

`deny → ask → allow`，第一个命中即生效，deny 优先级最高。

### 常用模式

- **default**：标准询问
- **acceptEdits**：自动接受文件修改
- **plan**：只读分析，不能改文件
- **dontAsk**：没预允许就拒绝

### 规则语法

- `Bash` = 所有 Bash 命令
- `Bash(npm run test:*)` = 前缀匹配
- `Bash(*)` ≠ 所有 Bash（别用）

### 配置模板

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)", "Bash(git status)", "Bash(git diff)"],
    "ask": ["Bash(git push)", "Bash(rm *)"],
    "deny": ["Read(.env)"]
  }
}
```

### 入口

- `/permissions` - 查看和调整权限
- `/config` - 设置默认模式
